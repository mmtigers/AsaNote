# おやノート 要件定義書 v0.3

離れて暮らす両親(父・母)が毎日の生活を簡単に記録し、家族がその記録を確認できるスマホ向けアプリ。
日々の記録を完了すると、孫の写真がランダムに1枚表示される。

> 状態: 要件確定(v0.3)。実装はタスク3(DB のスキーマ・権限)まで。実装と食い違う点を見つけたら、この文書を直す。
>
> 改訂履歴
> - v0.2: 初版の要件(プロンプトとして提示。ファイルとしては存在しない)
> - v0.3(2026-10-17): 既存資産(あさノート・よるノート)の調査結果を踏まえ、v0.2 の未確定事項をオーナーと合意して確定した(§10)。
>   未確定事項は無い(§11)。構成の詳細は [ADR 0001](adr/0001-architecture.md)。

## 1. 目的と前提

- 父・母が、それぞれ自分の1日の記録をスマホで手早く入力できる。
- 家族は、必要なときにアプリを開いて、父・母それぞれの記録を確認できる。
- 記録を続ける動機付けとして、記録の完了時に孫の写真を1枚表示する。
- アプリは評価・診断をしない。未記録の日を、体調不良や服薬忘れとして扱わない(§6)。
- 自動通知・プッシュ通知は MVP の対象外。

## 2. 利用者と権限

| 役割 | できること | できないこと |
|---|---|---|
| 親(父・母) | 自分の記録の作成・閲覧・編集。自分に表示された孫の写真の閲覧 | **もう一方の親の記録の閲覧**、写真・利用者の管理 |
| 家族管理者 | 父・母の記録の閲覧、写真の管理(追加・無効化・削除)、利用者の管理(招待・役割の付与) | 親の記録の作成・編集・削除(代理入力はしない) |
| 家族閲覧者 | 父・母の記録の閲覧 | 写真・利用者の管理、記録の作成・編集 |

- 家族管理者は**複数人**を置ける。家族管理者は閲覧者の権限を兼ねる。
- 権限は**サーバー(データベースのRLS・関数)側で検証する**。画面の出し分けだけに頼らない。
- 端末へ取り込むデータも、その利用者に読めるものに限る(RLSで絞る。もう一方の親の記録が端末に保存されることもない)。
- 未認証の第三者は、記録・写真にアクセスできない。

## 3. ログイン

- 親のログイン操作は最小にする。**メールの6桁コード**でログインし、ログイン状態を長く維持する(毎回のログインを求めない)。
- 認証とアクセス制御は省略しない。
- 既存アプリのメールのログインリンクは、iOS のホーム画面に追加したアプリでリンクが Safari 側で開き、ログイン状態が引き継がれないおそれがあるため採らない(実機で確認する。§9)。

## 4. 日次の記録

1日 × 1人(父または母)= 1件。同じ利用者・同じ日付の記録は重複して作られない(データベースの一意制約で担保する)。
記録の対象日は**日本時間(JST)**で決める。端末のタイムゾーン設定に依存しない。

### 4.1 項目

どの項目も「未入力」を持ち、選択した値と区別して保存する。

| ブロック | 項目 | 選択肢(初期案。後から調整できる設計にする) |
|---|---|---|
| 食事 | 朝食・昼食・夕食(個別) | 食べた / 少し食べた / 食べていない / (未入力) |
| 服薬 | その日の服薬 | 飲んだ / 飲んでいない / 未確認 / (未入力) |
| 活動 | 外出した | した / しなかった / (未入力) |
| 活動 | 買い物をした | した / しなかった / (未入力) |
| 活動 | 病院に行った | 行った / 行かなかった / (未入力) |
| その他 | 体調 | よい / ふつう / わるい / (未入力) |
| その他 | メモ | 自由記入(任意) |

- 服薬の「未確認」は「本人が飲んだかどうか分からない」、「未入力」は「まだ答えていない」を表し、両方を残す。
- 複数の薬の種類・服薬時刻の管理は対象外。
- 選択肢は1か所の定義に集約し、文言・並びを後から変更できるようにする。

### 4.2 入力・保存・完了

- 1画面でまとめて入力し、最後に「完了」を明示的に押す。
- **途中保存**できる。未完了のまま閉じても入力は失われない(端末内に保持する)。
- 一部の項目が未入力でも、本人が「完了」を押せば完了扱いにする。
- **完了は、サーバーへの保存成功を確認してから**完了扱いにする。通信できない間は完了できない(途中保存は可能)。
- 保存に失敗したときは完了扱いにせず、入力内容を保持したまま再試行できる。
- 過去の記録を閲覧・修正できる。**修正できる期間に制限は設けない**(未来の日付の記録は作れない)。
- 完了後に修正しても完了状態は維持する。完了を取り消す操作は設けない。

## 5. 孫の写真

- その日の記録を初めて完了したとき、孫の写真を1枚ランダムに選んで表示する。
- **完了状態と写真の表示履歴は、父・母で独立**させる。
- 写真が複数ある場合は、直前に表示した写真を候補から外し、同じ写真が連続しにくくする。
- その日に選ばれた写真は、同じ日なら**同じ写真をもう一度見られる**(新しい抽選はしない)。記録を修正しても再抽選しない。
- 写真の選択と「その日の写真」の記録は、サーバー側で1日1回だけ行う(何度修正・完了操作をしても写真が増えない)。
- 写真が登録されていない場合や、写真の読み込みに失敗した場合も、記録・完了は失われない(写真の表示は記録の保存と切り離す)。
- 親は、**自分に表示された写真だけ**を後から見返せる。
- 写真の追加・無効化・削除は家族管理者だけが行う。写真はアプリから家族管理者がアップロードする(外部ストレージ・NAS との連携はしない)。
- 写真は非公開のストレージに置き、未認証の第三者は取得できない。

## 6. 家族向けの閲覧

- 父・母の記録を個別に閲覧できる(父/母の切り替え)。
- 日付別の履歴を確認できる。
- 直近7日間の記録状況を確認できる。
- 週・月単位で、次の指標を集計する。
  - 完了した日数
  - 記録はあるが一部が未入力の日数
  - 未記録の日数
  - 服薬が「飲んでいない」の日数
- 日の状態は「完了」「記録あり(未完了・一部未入力)」「未記録」を区別して表示する。
- 未記録の日を、体調不良や服薬忘れと自動で判定しない。

## 7. 利用者の管理

- 家族管理者だけが招待コードを発行できる。発行時に役割(親 / 家族管理者 / 家族閲覧者)を指定し、参加した人にその役割が付く。
- 親・家族閲覧者は招待コードを発行できない。

## 8. 保存期間

- 記録・写真の保存期間は設けない(削除しない)。
- アカウントを削除したときは、その人の記録と表示履歴を削除する。

## 9. 構成と既存アプリとの関係

| 項目 | 決定 |
|---|---|
| リポジトリ | このモノレポに `apps/oya/` を追加する |
| フロントエンド | あさノート・よるノートと同じ Next.js(App Router)・TypeScript・Tailwind。共通コード `packages/core` を流用する |
| データベース・認証・写真の保存先 | **おやノート専用の Supabase プロジェクト**(Postgres・Auth・非公開の Storage)。あさノート・よるノートの本番DB・ログインとは共有しない |
| 配信 | おやノート専用の Vercel プロジェクト(Root Directory `apps/oya`) |
| DBへの反映 | おやノート専用のワークフローと Secret(既存の `SUPABASE_DB_URL` とは分ける) |
| スマホ対応 | PWA(ホーム画面に追加して使う) |

- 既存アプリへの影響を避けるため、`packages/core` の変更は必要最小限にする(core を変えると、あさノート・よるノートの両方で版上げが必要になる)。
- 既存のグループ共有の仕組み(同じグループなら全員の記録を読める)は、父・母の相互閲覧の禁止を満たせないため流用しない。
- 実機で確認すること: iOS・Android のホーム画面アプリで、6桁コードのログインと、ログイン状態の維持が期待どおり動くこと。

## 10. v0.2 の未確定事項の決定

| B6 | 過去の記録を修正できる期間 | 制限なし(§4.2) |
| B7 | 写真の同日再表示 | 同じ日は同じ写真をもう一度見られる。再抽選しない(§5) |

| C1 | 家族アカウントの招待 | 家族管理者だけが招待コードを発行し、役割を指定する(§7) |
| C2 | 週・月の集計指標 | 完了日数・一部未入力の日数・未記録日数・服薬「飲んでいない」の日数(§6) |
| C3 | 保存期間・削除方針 | 期限なし。アカウント削除時に削除(§8) |
| C4 | 孫の写真の取り込み元 | 家族管理者がアプリからアップロード(§5) |
