# よるノート 仕様書

子どもの帰宅から就寝までの夜のようすを、**寝かしつけ後に1画面でサッと**記録する家族向けPWA。
[あさノート](../../asa/README.md) の姉妹アプリとして、同じ技術スタック・UIの作法で作る。

> 状態: 第0〜2段階まで実装済み(§9)。実機での同期・共有の確認と過去メモの取り込みが残っている。決定事項は §10。実装と食い違う点を見つけたら、この文書を直す。

## 1. 目的と優先順位

| 優先 | 目的 | 設計への反映 |
|---|---|---|
| 1 | これまで面倒で記録していなかった情報を、寝る前に簡単に残せるようにする | 1画面・タップ中心・既定値あり・全項目任意(総合のみ必須)。「ざっくり」で済ませられること |
| 2 | 親が傾向を振り返る(何が荒れのきっかけか、何が効いたか) | 集計・タイムライン・「試したこと→結果」ログ |
| 3 | 学校・医療に状況を伝える | 期間指定の印刷/PDF・CSVエクスポート(あさノートを流用) |
| 4 | 親子のルール作りの材料にする | 検討事項ボード、効いた対応の可視化 |

**最重要の設計原則は「書く手間を減らす」こと。** 迷ったら項目を増やさず、入力を減らす側に倒す。

## 2. 対象ユーザー・利用場面

- 主な利用者: 子ども(複数可)を持つ保護者。夫婦で1グループを共有。
- 主な利用場面: 子どもが寝た後の数分。夜の最中は入力しない。
- 利用形態: スマホのホーム画面に追加したPWA。オフラインでも記録できる。

## 3. 記録モデル

**1日 × 1人の子ども = 1件の記録。** 兄弟姉妹は子どもごとに記録する(§6)。

### 3.1 項目

| ブロック | 項目 | 入力 | 必須 |
|---|---|---|---|
| 総合 | 今日の様子: 😌穏やか / 😣少し荒れた / 🌩大荒れ | 3択 | **必須** |
| 節目 | 帰宅・宿題開始・夕食・お風呂・消灯 | 帰宅・宿題開始・お風呂・消灯は**時間帯の3択ボタン**(帰宅: 14時より前/14〜15時/15時以降、宿題開始とお風呂: 15〜17時/17〜19時/19時以降、消灯: 20時より前/20〜21時/21時以降。もう一度押すと解除)。帰宅・宿題開始・お風呂は「ほか」から時刻も選べる。保存するのは帯(early/mid/late)か「ほか」で選んだ時刻(HH:MM。傾向ではその時刻が入る帯に数える)。夕食は時刻の候補ボタン+「ほか」。未入力可 | 任意 |
| 自由時間 | TV / YouTube / 読書 / ゲーム / 外遊び / お絵かき | タグ(複数、「＋追加」可) | 任意 |
| 友達 | 約束あり・約束なし | タグ(複数、「＋追加」可)。相手・場所などはメモへ | 任意 |
| 夕食 | 食べた / 少し / 食べず + 理由タグ(食べた: 好きなメニュー・お腹がすいていた・楽しく食べた・おかわりした、少し・食べず: においが苦手 など) | 選択 | 任意 |
| 荒れ | きっかけ・行動(号泣/物を投げる/暴言/家出 等)、親の対応と効いたか | タグ(複数)+○△× | 任意 |
| からだ | 疲れ・腹痛・食欲なし・イライラ・眠そう | タグ | 任意 |
| メモ | よかったこと・明日の予定なども含めた自由記述(最大2000文字)。**写真は同じ欄に添付**(1日5枚まで、カメラ/アルバム) | テキスト+画像 | 任意 |

- **全セクションを最初から展開して表示する**(タップして開く手間をなくす)。荒れの項目と夕食の理由だけは、該当する選択をしたときに出る。
- タグは初期セット(`src/constants/choices.ts` に集約)+ユーザー追加。よく使うものが上に並ぶ(あさノートの `reasonOptions` と同じ方式)。
- 「大荒れ」「少し荒れた」を選んだときだけ「荒れ」ブロックを展開する(穏やかな日は入力を増やさない)。

### 3.2 手間を減らす工夫(優先度1)

1. **前日の既定値**: 節目の時刻・自由時間タグなど、前日の選択を薄く提示し、1タップで引き継げる。
2. **時刻は手入力もプルダウンも不要**: 帰宅・宿題開始・お風呂・消灯は3つの時間帯ボタンをタップするだけ(帰宅・宿題開始・お風呂は外れる日だけ「ほか」で時刻)。夕食だけは3つの候補ボタン(使うほど「その項目でよく選ぶ時刻」の上位3つに入れ替わる)と、外れる場合の「ほか」の選択メニュー。個別の達成項目は持たず、節目だけで流れを残す。
3. **1画面完結 + 下書き自動保存**: あさノート同様、途中離脱しても復元。
4. **日記文の自動生成プレビュー**: 選んだ内容から文章を作る(あさノートの `recordPreview` 方式)。メモを書かなくても記録として残る。
5. **夜のリマインド**: 未入力の日の21時ごろにPush(時刻は設定可)。アプリを開いたときも、20時以降で今夜がまだ誰にも記録されていなければ(自分でもパートナーでも記録済みなら出さない)ホームにお知らせを出す(閉じればその日は非表示)。
6. **パートナーの記録状況**: パートナーが今夜の記録を済ませているとホームに表示する。希望者(各自の設定、既定OFF)には、パートナーが記録を追加した時点でPushも送る(`notify-evening-partner`)。
7. **読んだ・コメント**: これまでの記録(`/timeline`)の各カードに「読んだ」ボタンと、ひとことコメントを付けられる(あさノートと同じ。実装は `packages/core` の `RecordFeedback`)。「読んだ」は自分の記録にも押せ(未読/既読を見分けるため)、押すと「✓ 読みました M/D H:mm」になり、取り消しは無い。記録した人の画面にも、パートナーが読んだ日時が出る(まだなら「まだ読まれていません」)。コメントは1つの記録に1人1件・100文字までで、書いた本人だけが編集・削除できる。どちらもサーバーに同期済みの記録にだけ出す(表は `evening_record_reads` / `evening_record_comments`。RLS は記録が見える人=本人+同じグループのメンバー)。希望者(各自の設定「パートナーがコメントしたときの通知」、既定OFF)には、コメントが付いた時点(INSERTのみ。編集・削除では通知しない)でPushも送る(`notify-evening-comment`。合言葉は `notify-evening-partner` と同じ `EVENING_NOTIFY_SECRET`)。既読にしても通知は送らない。

### 3.3 荒れの記録の扱い

- 「荒れ」は、様子が「少し荒れた」「大荒れ」のときだけ展開する。タグは初期セット+ユーザー追加。
- アプリは評価・診断をしない。相談を促す案内文なども出さない(決定済み)。安全面の専用タグも設けない(決定済み)。気になる出来事はメモやタグ追加で記録する。

### 3.4 写真

- メモ欄に添付する。1日(1人)5枚まで。カメラまたはアルバムから追加し、保存前に長辺1600px程度へ縮小・JPEG圧縮する。
- 保存先は Supabase Storage(非公開バケット。グループのメンバーだけが読める署名付きURL)。メタデータは `evening_photos`(`record_id`, `storage_path`)。
- オフライン時は縮小済みの画像をDexieにBlobで保持し、通信できると順にアップロードする(記録本体と同じ同期キュー)。
- 記録を削除すると写真も削除する。エクスポート(印刷/PDF)には任意で含める。CSVには枚数のみ。

## 4. 画面

| ルート | 画面 | 内容 |
|---|---|---|
| `/` | ホーム(記録) | 月カレンダー、子ども切替、記録ボタン。フォームは同一ルート内(あさノート方式) |
| `/timeline` | これまで | 記録の一覧(子ども・様子で絞り込み)。各記録に「読んだ」とひとことコメント(§3.2-7) |

| `/export` | エクスポート | 期間・子ども(すべて/各子ども/未分類)指定の印刷/PDF・CSV(CSVは「子ども」列つき) |
| `/group` | 共有 | 子ども・グループ・通知の設定 |
| `/updates` | 更新履歴 | 全バージョンの変更点。ホームに最新版のお知らせを出し、開くと既読になる |
| `/login` | ログイン | メールのマジックリンク(あさノートと同様)。ログイン無しでも、この端末だけで記録できる |

更新履歴は `src/data/releases.ts` に新しい順で書く。ユーザーに見える変更を入れるときは追加して `package.json` / `package-lock.json` の version も同じ値に上げる(CI の `lint-build-test` の先頭 step「Release notes check」が検査。依存更新などは PR ラベル `no-release-note` か本文の `[skip release-note]` で除外)。

ホームのカレンダーは今日より後の日を選べない。ログアウトすると、この端末のPush購読(ブラウザ側とサーバーの行)・端末内のDB・入力途中の下書き・選択中の子ども・リマインドを閉じた日付を消す。想定外のエラーと存在しないURLは、日本語の専用画面(`error.tsx` / `global-error.tsx` / `not-found.tsx`)を出す。

下部ナビ: 記録する / これまで / 傾向 / 試したこと / 共有(`/export` はナビに無く、「これまで」の画面からのリンクで開く)。

### 4.4 試したこと・検討事項ボード(第2段階・実装済み)

- 試したこと: 「18時までにお風呂に入る」「宿題は30分で」のような**ルール変更**を、内容(100文字まで)・開始日・対象の子ども(全員も可)で登録。開始前14日と開始後(最大14日)の荒れ率・消灯の時間帯(最も多い帯)を並べて見られる。「やめた日を今日にする/再開」ができる。
- 検討事項: 「困ったこと」(200文字まで)を溜めて、解決したらチェックするボード。
- 家族で共有する設定情報なので、同じグループのメンバーなら誰でも閲覧・更新・削除できる(作成者は変更できない)。表は `evening_rules` / `evening_concerns`。

### 4.5 クイック記録(廃止)

ホームのワンタップ記録は、使われなかったため廃止した。荒れた日も、記録フォームの「今日はどうだった?」から入力する。

## 5. 傾向(集計)

- 様子の内訳、カレンダー表示(あさノート流用)。
- 宿題開始の時間帯 × 様子 / 消灯の時間帯 × 様子。
- 友達との約束の有無 × 様子。
- きっかけタグの集計、効いた対応の集計。
- 各項目(様子・宿題開始の時間帯・友達との約束・きっかけ・効いた対応)をタップすると、記録日数・最も多い曜日・月平均、日別/週別/月別の推移、該当する過去の記録(自分の分は編集へ)を出す。
- **あさノート連携(第2段階・実装済み)**: 夜の記録(日付D)と、あさノートの `records` のD+1・同じ子どもを論理結合(読み取りのみ・外部キーなし)。「消灯の時間帯(20時より前 / 20〜21時 / 21時以降)と翌朝」「夜の様子と翌朝」を出す。共有モードで、翌朝の記録が読めるときだけ表示する。

## 6. 複数の子ども

- 子どもは `children` として登録(人数制限なし)。記録は必ず特定の子に紐づく。
- ホーム・タイムライン・傾向に子ども切替(あさノートの `ChildSwitcher` 流用)。
- 兄弟への共通項目のコピー機能は廃止した。
- 子ども名はハードコードしない。

## 7. グループ共有とあさノートとの関係

要件: **最初は共有でも、後から完全に分けられる**こと。

方針:

1. データ層は `src/lib/db/` に閉じ込め、`groups` / `children` の参照を1か所(`lib/db/children.ts` など)に集約する。
2. よるノートのテーブルは**独立**させる(`evening_records` ほか)。あさノートの `records` と外部キーで結ばない。連携が要る箇所は `group_id` と `child_id` による**論理結合**にとどめる。
3. Supabase の接続先は環境変数のみで切り替え可能にする。
   - **共有モード**: あさノートと同じ Supabase プロジェクト。同じログイン・グループ・子どもを使い、朝夜を横断して見られる。
   - **分離モード**: 別プロジェクト。`groups` / `children` / 認証もよるノート側に持つ。
4. `groups` / `children` 系のスキーマとRLSは、あさノートと**同じ定義を持つ**(共有モードでは重複作成しない、分離モードではそのまま作る)ため、`schema.sql` を「共通部」と「よるノート固有部」に分けて管理する。

**決定: 初期設定は共有モード。** 共通表(`groups` / `group_members` / `group_invites` / `children` と認証)はあさノート側の `schema.sql` を正とし、よるノートは**自分の表だけ**を作る・変更する。
あさノートとよるノートが、同じDBへスキーマを別々のワークフロー(`db-deploy.yml` / `db-deploy-yoru.yml`)で自動適用するため、互いの表を消さないよう次を守る。

- よるノートの `schema.sql` / 自動適用は、よるノート固有の表・関数・ビューだけを対象にする(`DROP` を共通表に向けない)。
- 表名は衝突しないよう `evening_` を接頭辞にする。
- 共通表の変更が必要な場合は、あさノート側で行ってからよるノートが追随する。
- 分離モードに切り替える場合は、共通部のSQLをよるノート側へコピーして適用する。

この約束はCIで守っている。`npm run check:schema` が `schema.sql` の `evening_*` 以外への操作を許可リスト方式で検査し、`Supabase type drift check` が素のPostgres(あさノート側の共通表の最小スタブつき)へ `schema.sql` を2回流して、型 `src/lib/db/database.types.ts` との差分を確かめる。あさノート側で共通表の列が変わったら、`supabase/ci/shared-tables-stub.sql` と型を追随させる。

## 付録. 計測

ログイン中のみ、記録フローの節目(開始・下書きからの再開・保存・保存せず離脱)を、あさノートと共有している `analytics_events` 表へ書く(`src/lib/analytics.ts`)。`event_name` は必ず `evening_` で始め、あさノートの集計に混ざらないようにする。メモ・タグなど記録の内容は送らない(様子と日付のずれ日数のみ)。書き込み専用で、失敗しても記録の保存には影響しない。表の定義の正はあさノート側の `schema.sql`。あさノートと共通の掃除(`cleanup_old_logs()`)で、**365日より古い行は消える**。`properties` は2000字まで(check 制約)。
