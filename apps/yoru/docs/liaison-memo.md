# 連絡メモの下書き 仕様書

療育先などへ毎週送る「家庭での様子」のメモ(200字程度)の**下書き**を、直近1週間のあさノート・よるノートの記録から AI で作り、
決まった曜日・時刻に届ける機能。よるノート([SPEC.md](SPEC.md))の第3段階として作る。

> 状態: 仕様の検討中(未着手)。決定事項は §9。実装と食い違う点を見つけたら、この文書を直す。

## 1. 目的とコンセプト

- **「ゼロから書く手間」を「読んで直す手間」にする。** 毎週の文面を考える負担を減らす。
- 下書きは**記録の要約**であり、送る文面は親が仕上げる。**AI が療育先へ直接送ることはしない。**
- 週に1回、1週間の記録をまとめて振り返る機会にもなる。

## 2. 利用場面

- 例: 毎週木曜の夜に療育先へメモを送っている。木曜 13:00 に下書きが届き(Push 通知)、夜に読んで直し、コピーして送る。
- 夫婦のどちらが開いても同じ下書きを見られる(グループで共有)。

## 3. 設定(`/group` に「連絡メモ」の項目を足す)

設定は**子どもごと**に持ち、**グループで共有**する(どちらの親が変えても同じ設定)。

| 項目 | 選べる範囲 | 既定 |
|---|---|---|
| 使う/使わない | オン・オフ。オンにするとき、「記録を AI(外部のサービス)に渡して要約する」ことへの同意を1回だけ取る | オフ |
| 対象の子ども | グループの子どもから選ぶ | ー |
| 曜日 | 月〜日 | 木 |
| 時刻 | **1時間きざみ**(0:00〜23:00) | 13:00 |
| 文字数 | 100〜400字(50字きざみ) | 200字 |
| 宛先の呼び名 | 自由入力(20字まで)。文面の書き方の調整に使う | 療育先 |
| メモ欄も使う | オン・オフ。オフなら、記録の結果とタグだけを AI に渡す | オン |
| 書き方の見本 | 任意。過去に送った文面を3件まで貼り付ける(各400字まで)。「送った」文面がたまるまでの文体の見本 | 空 |

- Push 通知を受け取るかは**個人ごと**の設定にする(既存の `evening_notification_settings` に列を足す。既定はオン)。
- 書き方の見本は個人情報を含みうるため、**リポジトリにはコミットせず、DB にだけ保存する**(§10 Q6 と同じ方針)。

## 4. 下書きの作成(自動)

1. pg_cron が毎分 Edge Function `generate-liaison-memos` を呼ぶ(リマインドと同じ方式。`cron-*.sql` は手動で適用)。
2. 対象: 設定がオンで、**日本時間で今日が設定の曜日、現在時刻が設定の時刻以降**、かつ今週の分がまだ作られていない子ども。
   時刻を過ぎてから一定時間(例: 3時間)を過ぎたら、自動では作らない(画面の「今すぐ作る」で作れる)。
3. 対象期間: **直近7日**(作成日の6日前〜作成日)。あさノートは当日の朝の分まで、よるノートは前日の夜の分までが実質的に入る。
4. AI に渡すもの:
   - あさノート `records`: 日付、登校の結果、起床、きっかけ・理由・対応のタグ、体調、メモ
   - よるノート `evening_records`: 日付、総合、夕食、自由時間・友だち、きっかけ・行動・対応のタグ、対応の効果、からだ、メモ
   - その期間に有効だった「試したこと」(`evening_rules`)と、未解決の「検討事項」(`evening_concerns`)
   - 文体の見本: 直近に「送った」文面を最大3件。足りない分は設定の「書き方の見本」で補う
   - 設定の文字数・宛先の呼び名
5. 情報の最小化:
   - 子どもの名前は渡さず「本人」に置き換える。
   - メモ欄の友だちなどの固有名詞は、文面に出さないよう AI に指示する。
   - 「メモ欄も使う」がオフなら、メモ欄は渡さない。
   - 写真は渡さない。
6. 文面の構成(指示): ①1週間の全体の様子 → ②良かったこと・できたこと → ③大変だった場面と、家庭での対応・その効果 → ④相談したいこと(あれば)。
   記録に無いことは書かない。指定の文字数の ±10% に収める。
7. 下書きを `liaison_memos` に保存し、グループのメンバーのうち通知をオンにしている人に Push 通知「今週の連絡メモの下書きができました」を送る。
8. 例外:
   - 記録が1件も無い週は AI を呼ばず、状態を「記録なし」にして保存する(通知は送らない)。
   - API が失敗したら、次の呼び出しで再試行する(2. の一定時間内)。それでも失敗したら状態を「失敗」にする。

## 5. 画面(よるノートに `/memo` を新設)

- 開く経路: Push 通知 / ホームのお知らせカード(下書きがあり、まだ「送った」にしていない間だけ出す) / `/group` の「連絡メモ」からのリンク。
  下部ナビ(5項目)は増やさない。
- 子どもの切り替え(設定がオンの子どもが複数いるとき)。
- 今週の下書き: 表示と編集(文字数カウントつき)、**コピー**ボタン。
- 「作り直す」: 1週につき3回まで。「もっと短く」「やわらかく」などの指示を付けられる。
- 「今すぐ作る」: 予定の時刻を待たずに作る(届かなかった週や、試しに作りたいとき)。作り直しと同じ回数制限に数える。
- 「送った」: 押すと、編集後の文面を最終版として保存する。翌週以降の文体の見本になる。押した後も編集でき、「送った」を取り消せる。
- 過去の連絡メモの一覧(新しい順。最終版があれば最終版、無ければ下書き)。
- ログインしていない(端末だけで使っている)人には、ログインが必要な旨だけを出す。

## 6. データ

ルートの `supabase/schema.sql`(共通表)に置く。いずれあさノートからも参照するため、`evening_` は付けない。

### `liaison_memo_settings`(子ども1人に1行)

| 列 | 型 | 内容 |
|---|---|---|
| `child_id` | uuid PK → `children` | on delete cascade |
| `enabled` | boolean | |
| `consented_at` | timestamptz | AI に渡すことへの同意の日時(オンにした人が同意) |
| `weekday` | smallint | 0=日〜6=土 |
| `hour` | smallint | 0〜23(日本時間) |
| `target_chars` | smallint | 100〜400 |
| `recipient_label` | text | 20字まで |
| `include_memo` | boolean | |
| `style_examples` | text[] | 3件まで、各400字まで |
| `updated_by` / `updated_at` | | |

### `liaison_memos`(子ども × 週に1行)

| 列 | 型 | 内容 |
|---|---|---|
| `id` | uuid PK | |
| `child_id` | uuid → `children` | on delete cascade |
| `period_start` / `period_end` | date | `(child_id, period_end)` で一意(二重作成を防ぐ) |
| `status` | text | `generated` / `no_records` / `failed` |
| `draft_text` | text | AI の下書き(作り直したら上書き) |
| `final_text` | text | 「送った」ときの文面 |
| `sent_at` / `sent_by` | | 「送った」の日時と押した人 |
| `regenerate_count` | smallint | 作り直し・今すぐ作るの回数(上限3) |
| `model` | text | 使ったモデル(調査用) |
| `created_at` / `updated_at` | | |

- 権限(RLS): 子どもが見える人(作成者と同じグループのメンバー。`children` と同じ判定)が読み書きできる。
  `draft_text`・`status`・`model`・`regenerate_count` は Edge Function(service role)だけが書く。
- 列を変えたら `npm run db:types`。`schema.sql` は `main` へのマージで本番DBに自動適用される。

## 7. Edge Function

- `generate-liaison-memos`(`apps/yoru/supabase/functions/`)。
  - cron からの呼び出し: 合言葉(`x-cron-secret`)で確かめ、§4 の対象を全部処理する。
  - 画面からの呼び出し(作り直す・今すぐ作る): ログイン中の人の JWT で、子どもが見えるか・回数の上限を確かめてから作る。
- 処理の本体は `_shared/` に置き、テストを書く(既存の `reminderHandler.ts` と同じ形)。
- Secrets: `ANTHROPIC_API_KEY`、`LIAISON_MEMO_MODEL`(モデルを環境変数で切り替える)。デプロイは手動(`push-notifications-setup.md` に手順を足す)。
- 費用は子ども1人につき週1回〜数回の呼び出しで、ごく小さい見込み。

## 9. 決定事項

| # | 内容 | 決定 |
|---|---|---|
| L1 | 実装の方式 | アプリに組み込む(Edge Function → Claude API → DB に保存 → Push 通知)。外部の自動化ツールは使わない |
| L2 | AI に渡す情報 | 名前は「本人」に置き換え、固有名詞は文面に出さない。同意を取ってからオンにする |
| L3 | 置くアプリ | よるノート。表は共通表にし、いずれあさノートからも参照できるようにする |
| L4 | 設定できる項目 | 文字数・曜日・時刻(1時間きざみ)。ほかに宛先の呼び名・メモ欄の利用・書き方の見本 |
| L5 | 療育先からの返事の保存 | **不要** |
| L6 | 過去に送った文面の見本 | リポジトリには入れず、設定の「書き方の見本」に貼り付けて DB に保存する |
