# 連絡メモの下書き 仕様書

療育先などへ毎週送る「家庭での様子」のメモ(200字程度)の**下書き**を、直近1週間のあさノート・よるノートの記録から AI で作り、
決まった曜日・時刻に届ける機能。よるノート([SPEC.md](SPEC.md))の第3段階として作る。

> 状態: 仕様の検討中(未着手)。決定事項は §11、未決は §12。実装と食い違う点を見つけたら、この文書を直す。

## 1. 目的とコンセプト

- **「ゼロから書く手間」を「読んで直す手間」にする。** 毎週の文面を考える負担を減らす。
- 下書きは**記録の要約**であり、送る文面は親が仕上げる。**AI が療育先へ直接送ることはしない。**
- 週に1回、1週間の記録をまとめて振り返る機会にもなる。

## 2. 利用場面

- 例: 毎週木曜の夜に療育先へメモを送っている。木曜 13:00 に下書きが届き(Push 通知)、夜に読んで直し、コピーして送る。
- 夫婦のどちらが開いても同じ下書きを見られる(グループで共有)。
- ログインが要る(サーバーで作るため)。端末だけで使っている人には、ログインが必要な旨だけを出す。

## 3. 設定(`/group` に「連絡メモ」の項目を足す)

設定は**子どもごと**に持ち、**その子どもが見える人(作成者と同じグループのメンバー)で共有**する。どちらの親が変えても同じ設定になる。
最後に変えた人と日時を表示する。

| 項目 | 選べる範囲 | 既定 |
|---|---|---|
| 使う/使わない | オン・オフ。オンにするとき、AI に渡す内容(§5)を示して同意を取る(§12-1) | オフ |
| 対象の子ども | グループの子どもから選ぶ | ー |
| 曜日 | 月〜日 | 木 |
| 時刻 | **1時間きざみ**(0:00〜23:00、日本時間) | 13:00 |
| 文字数 | 100〜400字(50字きざみ) | 200字 |
| 宛先の呼び名 | 自由入力(20字まで)。文面の書き方の調整に使う | 療育先 |
| メモ欄も使う | オン・オフ。オフなら、記録の結果とタグだけを AI に渡す | オン |
| 書き方の見本 | 任意。過去に送った文面を3件まで貼り付ける(各400字まで)。「送った」文面がたまるまでの文体の見本 | 空 |

- Push 通知を受け取るかは**個人ごと**の設定にする(`evening_notification_settings` に `notify_liaison_memo` を足す)。
  既存の `notify_partner_*` と違い**既定はオン**とし、**行が無い人にも送る**(通知を受け取る購読がある人だけ)。
- Push は、よるノートの購読(`evening_push_subscriptions`)にだけ送る。あさノートだけを使っている人には届かない(第2段階で検討)。
- 書き方の見本は個人情報を含みうるため、**リポジトリにはコミットせず、DB にだけ保存する**(SPEC §10 Q6 と同じ方針)。

## 4. 作成のタイミングと対象期間

### 4.1 「回」(1週に1回の作成単位)

- 回は**予定日**(`due_date`: 設定の曜日に当たる日。日本時間)で識別する。1つの子どもにつき、予定日ごとに1件(`(child_id, due_date)` で一意)。
- 予定の日時 = `due_date` の設定の時刻(日本時間)。
- 今の回 = 今日以降で最も近い予定日の回。ただし今日が予定日なら今日の回。
  - 例: 木曜 13:00 の設定で、火曜に「今すぐ作る」→ 2日後の木曜の回の下書きになる。木曜 13:00 には、すでにあるので自動では作らない。

### 4.2 自動作成の判定

1. pg_cron が **10分ごと**に Edge Function `generate-liaison-memos` を呼ぶ(時刻は1時間きざみなので毎分は要らない。`cron-*.sql` は手動で適用)。
2. 対象: 設定がオンで、**現在時刻が「予定の日時」以降、かつ予定の日時から3時間以内**、かつその回がまだ無い(または「失敗」で再試行の余地がある)子ども。
   判定は「今日の曜日」ではなく**予定の日時**で行う(23:00 の設定で日付をまたいでも取りこぼさない)。
3. 3時間を過ぎたら自動では作らない(画面の「今すぐ作る」で作れる)。
4. 設定の曜日を変えた週は、新旧どちらの曜日でも作られうる(同じ週に2回作られることがある)。これは許容する。

### 4.3 対象期間

前回のメモと重ならず、抜けもないよう、**アプリごとに期間をずらす**。作成した日を `X` とする(通常は予定日。「今すぐ作る」ならその日)。

| 記録 | 期間 | 理由 |
|---|---|---|
| あさノート | `X-6` 〜 `X`(当日の朝を含む) | 予定日の朝の分までが入る |
| よるノート | `X-7` 〜 `X-1`(当日の夜は含まない) | 前回の予定日の夜(前回の作成後に記録される)を拾うため |

- 実際に使った期間(あさ・よるそれぞれの開始日・終了日)を `liaison_memos` に保存し、画面に「○/○〜○/○の記録から作成」と出す。

## 5. AI に渡すもの

### 5.1 どの記録を使うか(重要)

あさノート・よるノートとも、**子どもが0〜1人の家庭では、記録を常に「未分類」(`child_id = null`)で保存している**
(`resolveEffectiveChildId`。あさノート SPEC の決定事項)。そのため、単純に `child_id` で絞ると記録が1件も見つからないことがある。

- 対象の人: その子どもの作成者と、作成者と同じグループのメンバー(`children` の RLS と同じ範囲)。**ほかの人の記録は使わない**(Edge Function は service role で読むため、この絞り込みを必ずコードで行う)。
- 対象の記録: 上の人の記録のうち、`child_id` がその子ども、**または** `child_id` が null で、かつそのグループの子どもが1人だけの場合。
  子どもが2人以上いるときの未分類の記録は、どの子のものか分からないので使わない。
- 同じ日に複数の記録がある(夫婦がそれぞれ記録した)場合は、両方を渡す。記録した人の名前は渡さない。

### 5.2 渡す項目

- あさノート `records`: 日付、登校の結果(`outcome`)、起床の時刻・タグ、出発の時刻、付き添い・引き渡し、きっかけ・理由・対応のタグ、メモ。
  - **`condition_scale` は渡さない**(記録した親自身の体調で、しかもアプリでは扱っていない旧い列)。`struggled` も渡さない(旧い列)。
- よるノート `evening_records`: 日付、総合、節目の時間帯、夕食とその理由、自由時間・友だち、きっかけ・行動・対応のタグ、対応の効果、からだ、メモ。
  - 総合・夕食・対応の効果・節目の時間帯は id(`calm`・`early` など)で保存されているので、**表示用の日本語に直してから**渡す。
    Edge Function(Deno)はアプリの `src/constants` を直接読めないため、対応表を `_shared/` に複製し、アプリの定義と一致することをテストで確かめる(既存の `pushCommonSync.test.ts` と同じ方式)。あさノートの選択肢も同様。
  - タグはラベル(日本語)のまま保存されている(カスタムタグを含む)ので、そのまま渡す。
- その期間に有効だった「試したこと」(`evening_rules`): その子ども向け、または対象が全員(`child_id` が null)のもの。
- 未解決の「検討事項」(`evening_concerns`): **子どもとのつながりを持たない表**なので、子どもが2人以上の家庭では、ほかの子の検討事項が混ざりうる。
  第1段階では、**子どもが1人の家庭でだけ渡す**(2人以上なら渡さない)。
- 文体の見本: その子どもの直近の「送った」文面を最大3件。足りない分は設定の「書き方の見本」で補う。
- 設定の文字数・宛先の呼び名、今回の期間。

### 5.3 情報の最小化

- **子どもの名前は AI に渡さない。** メモ欄・書き方の見本・過去の文面に含まれる、グループの**すべての子どもの名前**を、渡す前に置き換える
  (対象の子ども → `{本人}`、ほかの子 → `{きょうだい}`)。
- AI には、本人を指すときは `{本人}` と書くよう指示し、返ってきた文面の `{本人}` を、Edge Function で子どもの名前に戻してから保存する(§12-2)。
- 親・友だち・先生などの固有名詞は、文面に出さないよう AI に指示する(機械的には消せないので、確実ではない。同意の画面でもそう説明する)。
- 写真、記録した人の名前・メールアドレスは渡さない。
- 「メモ欄も使う」がオフなら、メモ欄は渡さない。
- メモ欄の文章は「データ」として渡し、その中の指示には従わないよう AI に指示する。

## 6. 文面の作成と検証

1. 構成の指示: ①1週間の全体の様子 → ②良かったこと・できたこと → ③大変だった場面と、家庭での対応・その効果 → ④相談したいこと(あれば)。
   記録に無いことは書かない。です・ます調。見出しや箇条書き・記号(Markdown)は使わない。
2. 文字数は、改行を除いた文字数(書記素の数)で数える。指定の **±15%** を外れたら、1回だけ作り直しを頼む。それでも外れたら、そのまま保存する(画面で文字数が分かる)。
3. 空の応答・`{本人}` 以外の波かっこが残る、などの不正な応答は「失敗」とする。
4. 記録が1件も無い回は AI を呼ばず、状態を「記録なし」にする(通知は送らない)。

## 7. 画面(よるノートに `/memo` を新設)

- 開く経路: Push 通知 / ホームのお知らせカード / `/group` の「連絡メモ」からのリンク。下部ナビ(5項目)は増やさない。
- ホームのお知らせカード: 今の回の下書きがあり、まだ「送った」にしていない間、**予定日から6日後まで**出す(押さないまま次の回が来たら消える)。「失敗」のときも出す(「作れませんでした。もう一度作る」)。
- 子どもの切り替え(設定がオンの子どもが複数いるとき)。
- 今の回: 対象期間、状態、本文の編集(文字数カウントつき)、**コピー**ボタン。
  - 編集した本文は `edited_text` に自動で保存する(少し待ってから保存。夫婦で同時に編集したら、後から保存したほうが残る)。
- 「作り直す」: 1回につき3回まで(「今すぐ作る」も含めて数える)。「もっと短く」「やわらかく」などの指示を付けられる。
  編集済みの本文があるときは、「編集した内容は消えます」と確かめてから作り直す。
- 「今すぐ作る」: 今の回がまだ無いとき、予定の日時を待たずに作る。
- 「送った」: 押すと、その時点の本文を最終版(`final_text`)として保存する。押した後も編集でき、「送った」を取り消せる。
- 過去の連絡メモの一覧(新しい順。最終版、無ければ編集後の本文、無ければ下書き)。
- 状態ごとの表示: 作成中(「作っています」)/ 下書きあり / 記録なし / 失敗(理由と「もう一度作る」)。

### 権限(RLS と列の権限)

- 読む: 子どもが見える人(`children` の SELECT と同じ判定)。
- `liaison_memo_settings` の作成・変更: 子どもが見える人。`consented_*`・`updated_*` はトリガーで `auth.uid()` と現在時刻を入れる(クライアントの値は使わない)。
- `liaison_memos`: クライアントには行の作成・削除を許さず、**列単位の権限**で `edited_text`・`final_text`・`sent_at`・`sent_by` の更新だけを許す
  (RLS は列を区別できないため、`revoke update` → `grant update (列…)` で制限する)。`sent_by` はトリガーで `auth.uid()` にする。
  それ以外の列は Edge Function(service role)だけが書く。
- `schema.sql` は `main` へのマージで本番DBに自動適用される。

## 9. Edge Function

`generate-liaison-memos`(`apps/yoru/supabase/functions/`)。処理の本体は `_shared/` に置き、テストを書く(既存の `reminderHandler.ts` と同じ形)。

- 呼び出し方は2つ。
  - cron: 合言葉(`x-cron-secret`)で確かめ、§4.2 の対象を処理する。
  - 画面(作り直す・今すぐ作る): ログイン中の人の JWT を確かめ、その人から子どもが見えること、回数の上限を確かめてから作る。
    回数は `update … set regenerate_count = regenerate_count + 1 where regenerate_count < 3` のように**1文で数えて確保**する(連打で上限を超えない)。
- 二重作成の防止: 作る前に、その回の行を `generating` で確保する(`insert … on conflict do nothing`、または `locked_at` が空か古い行だけを `update`)。
  確保できなければ、ほかの呼び出しが作成中なので何もしない。`locked_at` から10分たった行は、止まったとみなして取り直せる。
- 1回の呼び出しで処理する子どもの数に上限を設け(例: 5人)、残りは次の呼び出しに回す(関数の実行時間の上限に収めるため)。
- AI の呼び出し: Claude API。Secrets は `ANTHROPIC_API_KEY`、`LIAISON_MEMO_MODEL`(モデルを環境変数で切り替える。既定値はコードに持つ)。
  タイムアウトを設け、失敗したら `attempts` を増やして `failed` にする(自動作成の判定の時間内なら、次の呼び出しで再試行)。
- 作成できたら、§3 の通知の対象者に Push を送る(作り直し・今すぐ作るのときは送らない)。
- デプロイは手動。`apps/yoru/docs/push-notifications-setup.md` に、Secrets の登録・関数のデプロイ・cron の SQL を足す。
- ログに記録の中身・下書きの本文を出さない(子どもの情報のため)。

## 11. 決定事項

| # | 内容 | 決定 |
|---|---|---|
| L1 | 実装の方式 | アプリに組み込む(Edge Function → Claude API → DB に保存 → Push 通知)。外部の自動化ツールは使わない |

| L6 | 過去に送った文面の見本 | リポジトリには入れず、設定の「書き方の見本」に貼り付けて DB に保存する |
| L7 | 未分類の記録 | グループの子どもが1人のときだけ、その子の記録として使う(§5.1) |
