# verify-handoff — 品質検証と引き継ぎ

同梱の `verify.sh`(このスキルのディレクトリ内)を使う。ソースは変更しない。出力は `<repo>/.claude/handoff/`(gitignore 対象)。

## 実行
```
bash <このスキルのディレクトリ>/verify.sh [--keep-going] [--only <repo相対ディレクトリ>] [--dry-run]
```
- 手順の定義: リポジトリの `.claude/verify.steps`(形式は `名前 | ディレクトリ | コマンド`、CI と同じ順に書く)。無ければ、リポジトリ直下 `package.json` の `lint → typecheck → test → build` を自動検出する。
- 既定は最初の失敗で中断。全体像がほしいときは `--keep-going`。終了コード 0=全成功 / 1=失敗あり / 2=使い方の誤り。
- 依存が未インストール(`node_modules` なし)なら、先に `npm ci`(ロックファイルどおり。更新はしない)。

## 失敗したとき
1. `latest.md` の失敗ログ末尾と、`.claude/handoff/logs/` の全文を読み、原因を特定する(最初のエラーが原因。後続は連鎖のことが多い)。
2. 自分の変更が原因なら直して、**失敗した手順だけ** `--only` で再実行 → 最後に全体を再実行。
3. 自分の変更と無関係(ベースでも失敗)なら、直さず「未解決」に書く。

## 引き継ぎメモ
実行後、`latest.md` の末尾「次の作業 / 未解決」に、次を**手で**追記する(検証の結果だけでなく、判断と文脈を残す):
- 完了したこと・変更したファイル(`git status` / `git diff --stat`)
- 失敗した検証と原因、未検証の項目
- 判断待ちの事項と、次にやること
前回分は `prev.md` に退避される(消えない)。次のセッションは最初に `latest.md` を読む。

## 制約
- 実行済みの手順だけが「PASS」。SKIP / DRY は検証していない。成功と報告するのは PASS のみ。
- E2E(Playwright)・DB 接続が要るテストは既定の手順に含めない(環境依存)。必要なら `.claude/verify.steps` に追加する。
